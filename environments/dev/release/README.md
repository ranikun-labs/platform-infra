# DEV release prerequisites

Each owner directory has an independent S3 backend key (`dev/release/<owner>/terraform.tfstate`). Configure the backend bucket and region as for the existing DEV roots. These roots create ECR repositories and GitHub publisher/deployer roles independently of ECS, so an image can be published before the service's first task definition is created. Do not apply without verifying the DEV account, region, state backend, cluster and service naming with the owner.

The account-wide `token.actions.githubusercontent.com` IAM OIDC provider must already exist and be managed by a single separate owner. Supply its exact ARN as `github_oidc_provider_arn`; verify it accepts the `sts.amazonaws.com` audience. No root here creates or modifies that shared provider. Each role trusts only its hard-coded GitHub repository and `dev-<workload>-publish` or `dev-<workload>-deploy` environment. Configure and protect those exact GitHub environments before enabling releases. Platform's `name_prefix` must match the existing platform root; `cluster_name` must match the existing DEV ECS cluster. Account and region are explicit, and the provider rejects another account.

`terraform output -json workloads` exposes each workload's repository URL and ARN, publisher and deployer role ARNs, ECS service name and task family. Configure the corresponding repository/environment variables `DEV_AWS_ACCOUNT_ID`, `AWS_REGION`, `DEV_ECR_REPOSITORY` (the repository name, equal to the service name), `DEV_PUBLISHER_ROLE_ARN`, `DEV_DEPLOYER_ROLE_ARN`, `DEV_ECS_CLUSTER`, `DEV_ECS_SERVICE`, `DEV_ECS_CONTAINER`, and `DEV_ECS_TASK_FAMILY`. The container and family match the service name. Follow the release workflow's environment placement and protection requirements.

Images have immutable tags and scan on push. No lifecycle policy deletes images: retain rollback digests and make any future cleanup a separately reviewed operation. Destroying a nonempty repository fails. Deployer can register task definitions only for its exact task family and pass only the service's existing task and execution roles to ECS. It can update only its exact ECS service to a revision of that family, including an earlier revision for rollback. DescribeTaskDefinition requires a wildcard resource because AWS does not support resource-level permissions for that read. Protect deployment environments accordingly. Release roles cannot manage infrastructure, delete ECR images or mutate other ECS services.

# DEV platform root

Local candidate only; no AWS resources have been created. Configure the S3 backend bucket and region at initialization. State uses `dev/platform/terraform.tfstate`, encryption and S3 lockfiles; provision and authorize the backend separately. Set the mandatory DEV account ID; the provider rejects other accounts. Pass shared root outputs explicitly: VPC, public/private subnets, cluster ARN, namespace ID and matching namespace name. No root reads another state. Provide an issued regional ACM certificate, approved ALB ingress CIDRs, and the verified Gateway readiness path. ALB sends all HTTPS requests to Gateway on 8080 and probes 9091. Verify Cloudflare origin restrictions, route precedence, OAuth and readiness before use.

Gateway and Core are private Fargate services with Cloud Map discovery. Platform owns Gateway-to-Core and ALB-to-Gateway rules. Shared owns database and Valkey ingress rules: pass the platform service security group outputs to its approved ingress maps, and do not grant platform permission to mutate shared security groups. Product roots own their Gateway-to-product rules. The Gateway baseline config sets its application and management ports and the Core auth URI from the service name and namespace; Core's application port is 8081. Configure all remaining real application settings, product routes, secrets and approved authentication explicitly. Verify the static DNS and route contract against deployed application versions; no reference authentication is enabled here.

Managed Valkey requires TLS. The currently production-wired Platform Core Identity Redis client has not been verified to use TLS, so keep managed Valkey off until separately approved TLS-capable Core and Gateway releases are verified against it. An existing separately verified private cache may be used instead when its connection and security contracts are approved. Do not point the current unverified client at the managed TLS endpoint.

The module creates a baseline task definition and uses it for the first service by default. A previously registered first revision may instead be supplied, but must have the correct Fargate awsvpc configuration, container name, roles and ports. Release automation owns subsequent revisions and must apply baseline changes to newly registered revisions. Terraform ignores subsequent task definition and desired count changes; setting either input later does not update a running service. For a controlled first deployment, both desired counts default to zero; apply platform, then pass its service security groups to shared and apply the approved database/Valkey rules. Once dependencies and runtime configuration are verified, manually set desired counts to one. Manual ECS desired-count changes also support a controlled 0→1 experiment. Coordinate across services and verify work, outbox, drain, readiness and Aurora recovery first. There is no automatic scheduler or request-driven startup: authentication, leases, concurrency, in-flight work, readiness, and shutdown contracts have not been verified.

Audit messaging is disabled unless `audit_contract` names an accepted contract, nonempty alarm actions, and existing producer and consumer roles whose names begin with the DEV platform name prefix. Product-owned producers must receive their own queue-scoped send policy from their owner root, not through this platform role policy. Enabling it creates encrypted SQS/DLQ, role policies and alarms; it does not deploy or claim an active consumer. Establish retry/visibility, idempotency, outbox recovery, redrive and alert ownership before enabling. The age alarm threshold is a 300-second starting value to review against the accepted contract.
